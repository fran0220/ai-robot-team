## 1. 围棋AI算法自研 vs 开源？技术壁垒？
**要点**
- **策略：自研为主，开源为辅**。
- **壁垒来源**：数据与标注、端侧推理优化、教学/评测算法、反作弊分析。

**解释**
- 底层推理框架与训练方法借鉴成熟开源（如 KataGo 体系），但核心模型、数据与工程化策略自研，以形成稳定可控的技术壁垒。
- 数据与标注：自建对弈/教学数据集，覆盖段位、场景、题型、错误类型；形成差异化训练分布。
- 端侧推理优化：针对 RK3587 NPU 进行 INT8/FP16 量化、算子融合与算力调度，达到低延迟与高稳定性。
- 教学/评测算法：围棋教学逻辑（错因分析、定式识别、形势评价解释）是产品差异化重点。
- 反作弊分析：自研“AI吻合度+行为学”联合模型，形成独有监管能力。

## 2. 视觉识别 99.5% 准确率如何实现？
**要点**
- **多模型融合**：端侧棋子检测 + 几何校正/线段检测 + 多帧融合判决。
- **标定与自适应**：出厂标定 + 动态标定 + 光照自适应。
- **工程化保障**：量化与鲁棒性训练 + 错误检测与恢复机制。
- **指标口径**：识别准确率、误判率、棋局更新延迟分开标注指标性质。

**解释**
- 端侧深度学习棋子检测（黑白/空位分类）结合传统几何校正，降低遮挡与反光误判。
- 出厂标定 + 运行时动态标定（几何畸变/棋盘位姿），光照自适应（可控 LED 补光 + 自动曝光/白平衡）。
- 模型量化与鲁棒性训练（不同材质、不同光照 100–2000 lux），并使用棋局一致性校验与异常回退。
- 指标口径：棋子识别准确率 ≥99.5%（L）、误判 ≤0.1%（L）、棋局更新延迟 ≤1s（L）。

## 3. RK3587 NPU 算力分配方案
**要点**
- **算力分层**：围棋模块仅负责视觉采集与机械执行，AI 推理由主控完成。
- **并行流水线**：采集/预处理与主控推理解耦。
- **性能目标**：端侧目标值(T) 以推理延迟与模型大小约束。
- **可扩展性**：模型分级与版本升级支持。

**解释**
- 围棋模块负责视觉采集与机械执行，AI 推理与策略评估在主控侧完成，口径与 @jarvis 保持一致。
- 视觉检测 → 局面解析 → AI 推理 → 动作规划形成流水线；推理与 IO、图像采集异步解耦。
- 性能指标性质区分：
  - 端侧目标值(T)：推理延迟 ≤50ms、模型 ≤10MB。
  - 实验室验证值(L)：多任务同时运行时整体响应 <1s。
  - 量产预期值(M)：在标准光照与装配条件下稳定达标。
- 模型分级（快速模式/高精度模式）动态切换，支持后续模型版本升级（ONNX/TensorRT）。

## 4. 本地 vs 云端取舍
**要点**
- **本地优先**：关键功能在本地完成。
- **云端增强**：只上传必要数据用于更新与运营分析。
- **合规价值**：端侧可控 = 隐私合规 + 成本可控。
- **容错策略**：断网可用、云端不可用可延迟同步。

**解释**
- 关键功能（视觉采集、AI 推理、机械控制）在本地完成，确保稳定性、隐私与实时性。
- 云端仅用于模型更新、数据备份、远程监考管理与大规模统计分析。
- 数据合规边界：
  - 上云数据：模型版本与设备日志、匿名化统计指标、必要的告警元数据。
  - 不上云数据：原始视频流、原始音频、棋手个人身份信息与完整棋局录像。
  - 权限控制机制：最小权限访问、分级授权、审计日志、数据加密与存储时限策略。
- 网络断开时保证核心功能不降级，云端不可用时本地缓存并延迟同步。

## 5. 监考反作弊系统技术难点
**要点**
- **多模态融合难度高**。
- **证据链完整性**。
- **误判控制**。
- **实时性要求**。
- **隐私合规**。

**解释**
- 棋谱 AI 分析、行为检测、音频分析、网络流量监测需统一风险评分模型。
- 告警触发后需自动截图、录像片段保存与时间轴标记，确保可追溯性。
- 动态阈值（根据棋手水平与局面复杂度调整 AI 吻合度阈值）与分级响应（Info/Warning/Critical）。
- 行为识别、AI 吻合度检测需近实时计算；通知裁判系统需保证低延迟可靠传输。
- 录像保存时限、访问权限、数据加密与最小化采集原则。
