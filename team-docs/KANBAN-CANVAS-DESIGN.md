# Kanban Canvas 看板设计方案

## 背景与目标
传统列式 Kanban 在大规模任务/多角色协作场景下灵活性不足，需要将主看板升级为 **Canvas 画布**（可拖拽、缩放、平移），并保留任务状态信息。

**核心目标**
- 任务卡片可自由拖拽到任意位置
- 画布可缩放（滚轮/控制按钮）与平移（拖拽空白区域）
- 按状态分区域展示，但可自由移动
- 保存任务位置（持久化）
- 左/右侧状态栏默认隐藏，可折叠

---

## 方案调研与选型

| 方案 | 优点 | 缺点 | 适配度 |
|------|------|------|--------|
| **@xyflow/react (React Flow)** | 成熟的节点画布，内置拖拽/缩放/平移/控制器；支持自定义节点；易与现有 React 体系集成 | 不是纯白板，背景/工具需要自行定制 | ✅✅✅ |
| react-konva | 低层 Canvas 渲染，性能高 | 需要大量自研交互/状态管理 | ⚠️ |
| @tldraw/tldraw | 白板体验完整 | 体积大、定制成本高；与业务卡片结合成本高 | ⚠️ |
| react-infinite-viewer + react-moveable | 适配画布/拖拽 | 组合成本高，需要大量 glue 代码 | ⚠️ |
| @dnd-kit + 自定义 Canvas | 无额外依赖 | 需自行实现缩放/平移与坐标系统 | ⚠️ |

### 结论
选择 **@xyflow/react**：在保证开发效率的同时提供成熟的画布交互（拖拽、缩放、平移、MiniMap、Controls）。适合快速构建 Kanban Canvas 原型，并可逐步扩展。

---

## 技术方案设计

### UI 结构
- 左侧：团队/Agent 面板（默认折叠）
- 中间：Canvas 任务画布
- 右侧：动态/活动流面板（默认折叠）

### Canvas 画布核心功能
- **TaskNode**：任务卡片作为节点
- **StatusZone**：状态区域背景（非交互节点）
- **拖拽**：React Flow 原生拖拽
- **缩放**：滚轮 + Controls (右下角)
- **平移**：拖拽空白区域

### 数据模型变更（Convex）
新增字段：
```ts
canvasPosition?: {
  x: number;
  y: number;
}
```
- 存储任务卡片在画布中的坐标
- 拖拽结束后写回 Convex

### 交互规范
- 默认显示全部任务，按状态区域分布
- 双击卡片打开详情（Modal）
- 右键菜单快速操作（状态切换、阻塞/解除等）
- 缩放控制器固定在右下角

---

## 任务状态与区域映射
- 使用状态列映射到画布 X 轴区域
- 拖拽结束后：
  - 更新 `canvasPosition`
  - 若落入新的状态区域，可同步更新 `status`

---

## 组件结构（建议）
```
MissionControl
 ├─ Header
 ├─ LeftDrawer
 ├─ RightDrawer
 └─ CanvasBoard
     ├─ ReactFlow
     │   ├─ StatusZoneNode
     │   └─ TaskNode
     └─ Controls / Background
```

---

## 后续可扩展方向
- 多用户实时位置同步（协同）
- 状态区间可拖拽调整大小
- 任务分组/聚类（AI 聚合）
- 画布视图保存（多视图/快照）

---

**结论**：`@xyflow/react` 是最适合当前需求的 Canvas 看板方案，开发效率高且扩展空间大，推荐作为 v1.0 看板升级的基础。
