## 1. 围棋 AI 算法：自研 vs 开源？技术壁垒？

**结论**：采用“开源引擎 + 自研评估层 + 规则/交互/安全层”组合。

- **开源（如 KataGo）**：成熟、强度高、落地快，适合核心棋力引擎；在 RK3587 等边缘端有成功案例。
- **自研**：针对围棋教学、对弈风格、可解释性、性能优化、端侧部署做定制；这是我们真正的产品壁垒。
- **技术壁垒**：
  - **端侧推理优化**：量化/蒸馏/稀疏化、NPU/GPU/CPU 混合调度
  - **互动性与体验**：棋盘识别 + 对弈状态追踪 + 语音/视觉交互
  - **安全与合规**：可控的策略、反作弊识别、日志审计
  - **长期数据闭环**：用户对弈数据 → 训练与评估优化

## 2. 视觉识别 99.5% 准确率如何实现？

**核心策略**：多源融合 + 场景约束 + 时序校验。

- **硬件层**：高分辨率摄像头 + 均匀补光 + 防眩设计
- **算法层**：
  - 棋盘定位：边缘/角点检测 + CNN 纠偏
  - 棋子检测：YOLO/Seg 模型 + 颜色/材质特征增强
- **时序一致性**：对局状态跟踪，多帧投票消除误判
- **物理约束**：棋子只能落子/提子，变化有规则范围
- **异常处理**：遮挡、手部干扰、反光等特殊情况单独识别

## 3. RK3587 NPU 算力分配方案

**分配原则**：AI 推理优先，视觉实时性优先，资源动态调度。

- **视觉检测模型**：占 NPU 主要算力（70%）
- **围棋引擎推理**：动态调度（30%），按对弈节奏分配
- **CPU/GPU 辅助**：语音交互、UI 渲染、规则引擎
- **调度策略**：
  - 空闲时段预计算
  - 对弈关键帧优先视觉
  - QoS 保障延迟

## 4. 本地 vs 云端取舍

- **本地（端侧）优先**：低延迟、断网可用、数据隐私
- **云端补充**：复杂分析、模型更新、数据汇总
- **混合模式**：对局核心逻辑本地完成，云端用于策略优化与学习

## 5. 监考反作弊系统技术难点

- **难点 1：遮挡识别**：手部/物体遮挡棋盘
- **难点 2：外部辅助**：手机/语音提示检测
- **难点 3：异常落子**：非法落子或多次落子

**应对方案**：
- 多摄像头融合/广角覆盖
- 语音/环境声检测
- 状态机约束 + 违规记录
- 异常行为实时提示
